2. CRM BACKEND (concluido - Go, SQLite memory.db)
-------------------------------------------------------------------
Arquivos em /root/hokma/backend/:
- crm_routes.go   -> CRUD de leads e interacoes
- crm_ai.go       -> resposta com IA (MiniMax via OpenRouter)
- crm_context.go  -> base de conhecimento (empreendimentos/condicoes)
- crm_telegram.go -> notificacao automatica de lead novo

Tabelas SQLite (memory.db, prefixo crm_):
- crm_leads (id, nome, telefone, origem, campanha, status, ia_ativa,
  criado_em, atualizado_em)
- crm_interactions (id, lead_id, canal, direcao, mensagem,
  origem_resposta, criado_em)
- crm_context (id fixo=1, conteudo, atualizado_em)

Rotas ativas (exigem header X-Hok-Token):
- GET  /crm/leads
- POST /crm/leads (cria/atualiza por telefone, dispara Telegram se novo)
- PATCH /crm/leads/{id}
- PATCH /crm/leads/{id}/ia
- GET  /crm/leads/{id}/interactions
- POST /crm/leads/{id}/interactions (humano responde -> desliga ia_ativa)
- POST /crm/leads/{id}/ai-reply (gera resposta IA, usa crm_context)
- GET  /crm/context
- PUT  /crm/context

Persona da IA: identifica-se como Adriana Chaves, nunca menciona ser IA,
tom humano estilo WhatsApp, usa so dados do crm_context.
Modelo: minimax/minimax-m2.5 via OpenRouter.

Todos os endpoints testados via curl e validados (lead, interacao,
toggle IA, resposta IA com e sem contexto, notificacao Telegram).
